# Experiments

## 1. 目的

本検証では，提案したコスト関数および経路探索手法が，実際の地理情報に対してどのように振る舞うかを調査します。特に，重みの変化に対する経路探索結果の変化と，その要因にフォーカスします。

また，地域による地理的特徴や登録状況の違いが探索結果に与える影響を調べ，コスト関数の妥当性とスタンドアロンデバイスへの適用可能性を評価します。

|---|---:|---:|---:|---:|

座標は経度，緯度の順に記載しています。

## 4. 検証項目

### 4.1 地理情報の登録状況

OSMにおける各指標の登録状況と，bgに格納された指標値の分布を調査します。地域による登録状況の違いを比較します。

対象とする指標は以下の4つです。

| 種別 | 指標 | 概要 |
|---|---|---|
| Node | rank | 道路の接続・分岐に関する指標 |
| Node | traffic_signal | 交通信号機に関する指標 |
| Way | width | 道路幅員 |
| Way | surface | 道路の路面状態 |

### 4.2 重みと経路探索結果の関係

重みを一定の刻み幅で変化させ，以下の項目を取得します。

- 経路上の各指標値の合計・平均
- 経路長
- 重複を除いた生成経路数
- 探索ノード数
- 処理時間

重みと経路上の指標値の関係をグラフ化し，線形的な変化に限らない経路選択の挙動を調査します。

### 4.3 コスト関数の評価

指標ごとの数値スケール，NodeとWayのコストの比率，欠損値処理などを確認し，重み付けが意図したとおりに機能するかを評価します。

### 4.4 地域特性による比較

ノード密度，道路網の構造，指標の登録状況などを比較し，地域によって経路探索結果が異なる要因を考察します。

### 4.5 探索性能とデバイスへの適用

処理時間，探索ノード数，メモリ使用量，グラフデータ容量などを調査し，ESP32-S3を用いたスタンドアロンデバイスへの適用可能性を検討します。

**注意**

処理時間は実行環境や負荷に左右されるため，異なる環境間での単純な比較には適しません。同一環境での相対的な比較を基本とします。

## 6. 実験の実行方法

### 6.1 地理情報の登録状況

`coverage` は，OSMのPBFファイルと変換後のbgファイルを読み込み，Way指標とNode指標の集計を行う実験プログラムです。

実行形式：

```bash
./build/experiments/coverage <source.osm.pbf> <graph.bg> <way_tag1> [way_tag2] ...
```

実行例：

```bash
./build/experiments/coverage \
  data/minato/source.osm.pbf \
  data/minato/graph.bg \
  width surface
```

実行結果をファイルに保存する場合：

```bash
./build/experiments/coverage \
  data/minato/source.osm.pbf \
  data/minato/graph.bg \
  width surface \
  > data/minato/experiments/coverage.txt
```

他の地域についても，同様に対象ファイルのパスを変更して実行します。

### 6.2 重みを変化させる実験

`nodestepweight` と `waystepweight` は，それぞれNode指標とWay指標の重みを変化させ，経路探索結果を取得する実験プログラムです。

Node指標の場合：

```bash
BG_FILE=data/minato/graph.bg \
RESULT_DIR=data/minato/experiments \
./build/experiments/nodestepweight
```

Way指標の場合：

```bash
BG_FILE=data/minato/graph.bg \
RESULT_DIR=data/minato/experiments \
./build/experiments/waystepweight
```

実行後，対象とする指標を選択します。重みは -1 から 1 まで変化させ，各重みに対する経路探索結果を取得します。

地域を変更する場合は，`BG_FILE` と `RESULT_DIR` を対象地域のパスに変更します。

### 6.3 実験結果の可視化

実験プログラムが出力したデータは，gnuplotなどを用いて可視化します。

描画用データと画像ファイルは，対象地域の `experiments/` 以下に保存します。

## 7. データの意味と注意点

### 7.1 Way指標の登録率

Way指標の登録率は，対象となる `highway` Wayのうち，OSM上で指定したタグを持つWayの割合です。

例えば，`width` の登録率が低い場合，OSMに道路幅員の情報が登録されていないWayが多いことを意味します。

ただし，タグが登録されていることと，その値が正確であることは別の問題です。

### 7.2 Node指標の非ゼロ率

Node指標の集計では，bgに格納された指標値が0より大きいノードの割合を出力します。

これはOSM上の登録率ではありません。Node指標は変換時に初期値0で生成され，評価・検証・正規化を経てbgに格納されます。そのため，0という値が必ずしも未登録を意味するわけではありません。

特に `rank` は道路の接続・分岐に関する指標であり，値が0であるノードも正常な値を持っています。非ゼロ率は，指標値が正となるノードの割合として解釈します。

`traffic_signal` についても，同様に非ゼロ率を登録率と呼ぶことはできません。

### 7.3 指標値の正規化

bgに格納される指標値は，grapherによって正規化されます。基本的に各指標値は0から1の範囲になります。

このため，bg内の指標値は元のOSMタグの値そのものではありません。異なる地域間で比較する場合も，各地域の最大値・最小値に依存することに注意が必要です。

### 7.4 NodeとWayの集計対象

Way指標はOSMの `highway` Wayを対象とします。Node指標はbgに格納された全ノードを対象とします。

したがって，Wayの総数とNodeの総数は異なり，それぞれの割合を同じ意味で比較することはできません。
