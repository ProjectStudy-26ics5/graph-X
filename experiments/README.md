# Experiments

## 1. 目的

本検証では，提案したコスト関数および経路探索手法が，実際の地理情報に対してどのように振る舞うかを調査します。
特に，重みの変化に対する経路探索結果の変化と，その要因にフォーカスします。
また，地域による道路網の構造や地理情報の登録状況の違いが探索結果に与える影響を調べ，コスト関数の妥当性とスタンドアロンデバイスへの適用可能性を評価します。

## 2. 対象地域

異なる地理的特徴を持つ以下の5地域を対象として，選びました。

## 3. 検証項目

### 3.1 地理情報の登録状況

OSMにおける各指標の登録数・登録率・値の分布を調査する。欠損値と実際の値0は区別し，地域による登録状況の違いを比較します。

### 3.2 重みと経路探索結果の関係

重みを一定の刻み幅で変化させ、以下の項目を取得します。

- 経路上の各指標値の合計・平均
- 経路長
- 重複を除いた生成経路数
- 探索ノード数
- 処理時間

重みと経路上の指標値の関係をグラフ化し，線形的な変化に限らない経路選択の挙動を調査します。

### 3.3 コスト関数の評価

指標ごとの数値スケール，NodeとWayのコストの比率，欠損値処理などを確認し，重み付けが意図したとおりに機能するかを評価します。

### 3.4 地域特性による比較

ノード密度，道路網の構造，指標の登録状況などを比較し，地域によって経路探索結果が異なる要因を考察します。

### 3.5 探索性能とデバイスへの適用

処理時間，探索ノード数，メモリ使用量，グラフデータ容量などを調査し，ESP32-S3を用いたスタンドアロンデバイスへの適用可能性を検討します。
> [!CAUTION]
> 処理時間に関しては，環境に左右されるので参考程度にしかなりません。

## 4. データ構成

地域ごとに元のOSMデータ，生成したグラフbg，検証結果を分けて管理しています。

```text
data/
├── minato/
│   ├── source.osm.pbf
│   ├── graph.bg
│   └── experiments/
├── takao/
├── nerima/
├── edogawa/
└── hachijo/

```

検証結果はCSV形式で保存し、gnuplotなどを用いて可視化します。
